## What Went Well

1. **Epic 7 retro commitments held this time.** Of the 12 trackable commitments from Epic 7's retro, **9 held cleanly, 2 partially held, and 1 (technical-debt carries) deferred**. That is a complete inversion of Epic 7's "2 held, 5 broken" pattern. The single most important commitment — reinstating the adversarial code-review gate — was honoured on both 8-1 (commit `62265ae` is literally titled "Story 8.1 code-review fixes — H1 + M1-M4") and 8-2 (code-review pass before status flip to `done`). The course-correction worked.

2. **Real-DB integration test framework — delivered as Epic 8 prep, not deferred a fourth time.** Epic 6 retro flagged it, Epic 7 retro re-flagged it as "non-negotiable, last chance." Story 8.2 actually used it: `apps/api/src/trpc/routers/__integration__/user.int.spec.ts` exercises RLS enforcement (cross-user reads must return zero rows), CHECK-constraint rejection of bogus locales, and `ON CONFLICT … DO UPDATE` `updated_at` bump semantics. The framework is now load-bearing — the next story that touches `users` or any RLS-policed table can lean on it.

3. **`(admin)/layout.tsx` Clerk async bug cleared.** Waived across Stories 7-1, 7-2, 7-3 — fixed during Epic 8 prep (commit `4a0189b`). The type error that compounded for 3 epics is gone. Story 8-1's locale-segment migration then piled on top of a clean foundation instead of a broken one.

4. **`project-context.md` updated as commitments, not aspirations.** Epic 5/6/7 retros all committed to lifting recurring patterns into `project-context.md` and all defaulted. Story 8-1 added the i18n rule under Frontend Rules. Story 8-2 added two more (LanguageSwitcher usage + four-place locale-adding rule). Project context now carries 60+ rules and is the canonical place a new agent reads first.

5. **Story 8-1's three-phase cadence was the right call.** A single-shot dev cycle for the largest cross-cutting refactor in project history (every component in `apps/web` becomes a `t(...)` consumer) would have been unsafe. Splitting into Phase 1 (framework + routing migration), Phase 2a (admin/dashboard surface + CI scripts), Phase 2b (full string sweep + plugin refactor), and a code-review-fixes pass kept each cycle bounded. CI gate was green at every phase boundary.

6. **The `[locale]` segment migration mechanical move was clean.** Moving `(admin)`, `(judge)`, `(presenter)`, `(public)`, `(auth)` under `apps/web/src/app/[locale]/...` and swapping every `next/link` / `next/navigation` import for `@/i18n/navigation` was a five-figure-line refactor on the surface. It landed in Phase 1 with no test regressions because the substitution was 1:1 and the typesystem caught the rare mistake.

7. **Format-plugin string ownership resolved cleanly (Story 8-1 Task 8).** A Day-1 architectural decision ("plugins are domain-agnostic libraries") finally had a concrete answer: plugins expose a typed `Labels` interface; the host (apps/web) wires translated strings via props. `JudgeVoteInput` and `JudgeScoreInput` in `packages/formats/cypher-battles` now accept `labels?: Partial<Labels>` with English defaults for backward-compatible tests. The pattern is reusable for any future format plugin.

8. **Adversarial review on 8-1 caught a real AC violation post-implementation.** The H1 finding ("`[locale]/page.tsx` boilerplate had ~10 hardcoded English strings the original sweep missed") was a literal violation of AC #1, caught by the review pass. M2 ("delete the temporary i18n-switch POC") and M3 (`score-override-manager` still importing `useRouter` from `next/navigation`) were both small but represented residual drift that would have rotted. The gate paid for itself on the very story where it was re-established.

9. **Story 8-2 demonstrated end-to-end story-cycle in a single session.** Create-story → dev-story (12 tasks, 5 surface layouts, new DB table, new tRPC router, real-DB integration test) → code-review (independent, different model strongly preferred) → done. The story file accumulates Dev Agent Record + File List + Change Log along the way, and the sprint-status flip is automatic. This is the cleanest end-to-end the project has had since Epic 6.

10. **Three-layer persistence architecture (cookie + localStorage + DB) holds without state divergence.** `<LanguageSwitcher>` writes both client-side persistence layers atomically. `<LocaleBootstrap>` reads localStorage when cookies are cleared (Safari ITP, private mode). `<OrganizerLocaleReconciler>` reads the DB-backed preference for authenticated users. The precedence is documented in `apps/web/src/i18n/README.md`. There is one race (organizer A switches on phone, organizer A's open laptop session doesn't react in real-time) — documented as next-page-load semantics by design.

11. **Spanish review pass actually shipped inside Epic 8, not deferred.** Story 8-1 explicitly deferred Spanish quality to "Story 8-2 or a follow-up." Story 8-2 absorbed it as Task 8 and applied the targeted fixes (`Puesto de juez`, `Cabeza de serie #{seed}`, `CONFIGURACIÓN`, panel subtitle smoothing). 610-key parity preserved. The "follow-up story" trap was avoided.

## Breakthrough Moments

1. **Server-side reconciliation moved to a client component without losing semantics.** The Story 8-2 spec originally proposed a server-side reconciliation in `(admin)/layout.tsx` that would call `getPreferences.query()` and `redirect()` server-side. Problem: `createServerTrpcClient` had no auth-token plumbing, and adding it would have meant pulling Clerk's `auth().getToken()` into the layout's render path. The implementation pivoted to a client component (`<OrganizerLocaleReconciler />`) using `trpc.user.getPreferences.useQuery({ enabled: isSignedIn })`. This has natural retry semantics, doesn't require server-side token forwarding, and the user perceives no difference (the client-side redirect fires before any meaningful content render). The spec's debug-log section captures this pivot.

2. **First-sign-in seeding heuristic.** When an organizer signs in for the very first time, no row exists in `users` and `getPreferences` returns `{ preferredLocale: 'en', hasPreference: false }`. If the URL the user landed on is `/es/...`, the reconciler treats that as deliberate intent and seeds the row with `'es'` — it does NOT redirect them to `/dashboard`. This is the right semantics: the URL expresses the user's intent before the DB knows about them. Captured cleanly with a single `hasPreference` discriminator on the response. (The linter-applied diff added this discriminator post-initial-implementation; it's tighter than the original heuristic of "stored == 'en' AND URL == 'es' implies seed".)

3. **`locale-switch-pending` sessionStorage flag prevents reconciler race.** A subtle race: user clicks the switcher → `<LanguageSwitcher>` fires `router.replace(pathname, { locale: next })` AND `setPreference.mutate({ locale: next })`. The router replace lands first, the admin layout re-renders, `<OrganizerLocaleReconciler>` reads `getPreferences` (still returning the OLD locale because the mutation hasn't committed yet), and would redirect the user BACK to the old locale. Fix (added during code-review fixes): the switcher writes `sessionStorage.setItem('locale-switch-pending', '1')` before navigating; the reconciler reads-and-clears it on next mount and skips reconciliation that cycle. Documented inline. Small flag, ugly race, clean fix.

4. **`users` table reuses `session.current_organizer_id` despite the name.** The session variable is misleadingly organizer-specific; its actual value is whatever Clerk `userId` is authenticated. Reusing it for the new `users_self_only` RLS policy keeps every router's `SET LOCAL`/`set_config` pattern uniform. Renaming the variable would have cascaded into every existing router — explicitly out of scope, documented as a known tech debt for a future refactor story.

5. **Defence-in-depth at three layers for locale validity.** A locale value must survive three checks: Zod enum in `setLocalePreferenceSchema` (catches client-side input), router-level validation via next-intl's `hasLocale`, and DB-level CHECK constraint `preferred_locale IN ('en', 'es')`. Any one would suffice; all three is the right paranoia for a value that propagates across cookies, localStorage, DB, URL, and three reconciliation layers. The integration test exercises the DB level explicitly.

6. **Story 8-1's runtime-switching POC was useful, then deleted, exactly as designed.** `apps/web/src/components/dev/i18n-switch-poc.tsx` was created in Phase 2a to prove the runtime-switch actually worked, then explicitly deleted in the Story 8-1 code-review fixes pass (M2 finding). The discipline of "build it to prove the framework works, delete it before merge" held. Story 8-2's real `<LanguageSwitcher>` replaces it cleanly.

## Team Agreements Going Forward

These are the discipline commitments to carry into whatever comes after Epic 8.

1. **Maintain the adversarial review gate.** Both Epic 8 stories had a CR pass. Epic 9 (if it exists) must keep this — the cost of slipping again is much higher than the cost of running the gate.
2. **Code-review LLM must differ from implementer LLM.** Document the implementer model and the reviewer model in every story's review section. (Story 8-2 honoured this; Story 8-1's pattern is the anti-precedent.)
3. **Real-DB integration tests are part of the standard toolkit now.** Every new RLS-policed table or TOCTOU-sensitive procedure gets an `*.int.spec.ts` next to its unit spec.
4. **`project-context.md` updates land alongside the story that discovers the pattern.** Continue the discipline from Epic 8 — don't backslide to "carried 3 epics."
5. **devDeps need acknowledgement too, not just runtime deps.** Tsx slipping in is the only documented case; lock it in before it becomes a pattern.
6. **Pre-commit code-review for high-fanout phases (>20 files).** New discipline from this retro. Untested in practice — try it on the first high-fanout cycle of whatever comes next.
7. **Sprint-end hygiene: flip epic to `done` when last story flips.** Catch it before retro time. Two retros in a row caught this manually.
8. **NO production deploy without E2E coverage of the golden path AND deep manual venue testing on real hardware.** Both gaps inherited. Don't ship to real users without closing them.
