## What Went Well

1. **Pure-domain `domain/` folder pattern proved itself.** Story 5-1 introduced `bracket-generator.ts` as a no-DB pure module. Story 5-3 followed the precedent twice over with `vote-tallier.ts` and `round-builder.ts`. 18 unit tests across the three modules, zero DB mocks. This is now the cleanest part of the codebase and the precedent for any future algorithmic logic in API.

2. **Four-layer idempotency stack got named explicitly.** Story 5-3 dev notes codified the four distinct idempotency layers in Battles (by-key on votes, by-state on completion, by-state on tie-limbo, by-conflict on round materialization). Naming them prevents the next person from adding a fifth layer that overlaps and conflicts. Worth memorializing in `project-context.md`.

3. **Synchronous post-vote tally was the right architectural choice.** Story 5-3 deliberately kept tally + advancement + completion inside the same vote-submission transaction instead of using a worker queue. Trade-off documented: vote tail latency includes ≤2 INSERTs + ≤1 UPDATE common case, ≤8 INSERTs at competition completion. Collapses an entire class of "blank gap between rounds" race conditions and keeps the bracket invariant ("every matchup with `winnerCompetitorId IS NOT NULL` has a `matchup.completed` event in the same competition's stream") atomic.

4. **Adversarial review gate continued to pay for itself.** All three stories had review-pass HIGH findings that real bugs — Story 5-1 (concurrent generation race), Story 5-2 (broadcastVoteSubmitted didn't reach judges + migration drift), Story 5-3 (sequence-collision crash + idempotent re-emit drift). All resolved before `done`. Across Epic 2 → Epic 5 the gate has caught a HIGH issue in essentially every story.

5. **Zero new runtime dependencies — fourth epic in a row.** Battles, voting, advisory locks, sequence handling, tie resolution UI, audit-trail integration — all built with existing workspace deps + Drizzle + Zod + nanoid + native Postgres advisory locks. The "no new deps" discipline established in Epic 2 is holding.

6. **Mock-gateway preemption finally worked.** Story 5-3 dev notes called out the recurring mock-gateway oversight from Stories 4-3, 5-1, 5-2 and _led_ with adding all 5 new `vi.fn()` entries to BOTH `mockGateway` and `makeFullGateway()` before writing implementation. That worked — review didn't flag it. (The same defensive thinking missed the events-table 23505 wrap, however — see below.)

7. **Project-context.md is load-bearing.** Story 5-3 references it 11 times in dev notes. The Epic 2 commitment to consolidate gotchas is visibly returning compounding value across every subsequent story.

## What Was Challenging / Recurring Struggles

1. **The "add N similar things at once → systematic guard becomes the first casualty" pattern.**
   - Story 5-2 added the per-judge fan-out for `vote.submitted` and forgot to apply it to all judge rooms (HIGH H1, fixed in review).
   - Story 5-3 added 5 new event-INSERT sites in helpers + `resolveTie` and forgot the 23505 → INTERNAL_SERVER_ERROR wrap on every one of them (HIGH H1, fixed in review).
   - The mock-gateway-omission pattern (Stories 4-3, 5-1, 5-2) was finally defended against in 5-3 — proving the team CAN preempt these — but the defensive thinking didn't transfer to the structurally similar events-table case.
   - **Root cause hypothesis:** when you copy-paste 5 similar blocks, you copy-paste their bugs too. Need a helper or generator pattern that makes the safe path the only path.

2. **Real-DB integration tests still don't exist** (Epic 2 commitment, 4 epics later).
   - Story 5-3's H1 (concurrent matchup completions racing on `events.sequence`) is exactly the bug class real-DB integration tests catch cheaply.
   - Caught here by adversarial review. Will be caught later in production by users.

3. **Playwright E2E happy path still doesn't exist** (Epic 2 commitment).
   - The happy path now spans cypher start → score → complete → bracket gen → vote → progress → champion display → completion event broadcast. That's 5 epics' worth of coupling with no automated end-to-end verification.

4. **Post-commit broadcast pattern is copy-pasted everywhere.**
   - 5+ mutations now reproduce the "set `broadcastPayload` inside tx, emit after `await tx.commit()`" dance.
   - Story 5-3 took the first consolidation step with `emitMatchupBroadcasts()` (batches related broadcasts) but the inside-tx assignment and the `if (broadcastPayload !== null)` gate are still hand-written.

5. **`getBracket` response shape extension was a soft breaking change handled by good defaults.**
   - Adding `championCompetitorId` and `currentRoundNumber` as optional fields kept Story 5-1's `BracketViewPanel` working — but the test for "old consumer ignores new fields" was implicit, not explicit.

6. **No deployment to a live environment yet.**
   - Epic 5 closes a major user journey (cypher → battles → champion). Still all local. Some classes of issues (real WebSocket fan-out latency, real Postgres advisory lock contention, real Clerk JWT round-trips) only show up against real infrastructure.

## Breakthrough Moments

1. **Story 5-3's `insertEventOrRetry()` helper (added during review fix H1)** — first consolidation of the 23505-safe insert pattern. Should be applied retroactively to the older mutations that still hand-roll it.

2. **Story 5-3's `getBracket` response extension** — exposing `championCompetitorId` + `currentRoundNumber` as derived fields in the same query unblocks Epic 6.2's public bracket without a new procedure. Read-shape extension > new endpoint.

3. **Story 5-3 dev notes codified four idempotency layers as a single named pattern.** Future Battles work has a clear vocabulary.

4. **Pre-empted the mock-gateway oversight by editing test mocks first.** Story 5-3 dev notes explicitly called out "Stories 4.3 / 5.1 / 5.2 each forgot a new gateway method on first pass — preempt the recurring miss." This worked. The discipline is now meta-aware.

5. **Per-matchup advisory locks (`pg_advisory_xact_lock(hashtext('matchup-outcome:{id}'))`)** — pattern from Story 4-4 (`org-session:` lock) reused with a different key. Story 5-3 explicitly documented this as the reuse precedent. This is exactly the kind of cross-story pattern transfer the consolidated gotchas doc was meant to enable.
